# Working on World Cup Lens

World Cup Lens is a Next.js 16.4.5 / React 19 / strict TypeScript football intelligence app using Supabase, OpenAI embeddings and Responses structured outputs, API-FOOTBALL, and Tailwind/Radix UI. The public product is a credential-free, 104-match historical archive with original retrospective Match Lenses; private Supabase archive access requires exact server opt-in. The public fictional lab is retired; synthetic fixtures remain in testing. Ingestion and generation retain protected legacy-operation APIs.

## Work and verify
Inspect git status and relevant files before editing; preserve unrelated changes. Make small changes with one reviewable purpose. Distinguish observed behavior, inference, and planned behavior; cite paths and symbols. Do not claim deployed behavior or database guarantees from TypeScript alone.

Use Node 22.13.0 or newer within major 22 (`.nvmrc` selects major 22); install locked packages with `npm ci`. `.github/workflows/ci.yml` runs push/PR checks with dummy settings and no secrets.

Commands: `npm run check:data` validates the complete local factual/editorial module without network access. `npm run dev` (development), `npm run lint`, `npm run typecheck` (generates Next route types before checking), `npm run build`, `npm start` (built server). `npm test` compiles deterministic TypeScript tests into a temporary directory and runs Node’s test runner without external credentials or new dependencies. `npm run test:demo-http` checks unset/invalid server policy, missing service keys, blocked local authoring methods, and no service fetches. `npm run test:replay-http` explicitly opts into archive-enabled mode and starts local Next/mock Supabase servers to check rendered pages with dummy credentials; it requires localhost socket access and no other running Next dev server for this checkout. Requests time out after 15 seconds, the run has a 120-second watchdog, and local process-group cleanup is bounded. `npm run test:production-http` is an explicit remote smoke check of the authorized public demo (optional `DEMO_URL`); it sends no auth/service credentials and checks blocked methods only after confirming demo policy. It is separate from local CI. `npm run test:design` optionally uses an existing isolated Chromium binary against a running demo build on localhost:3107; it captures five widths and checks navigation/focus/overflow without downloading browsers or using user profiles. See `docs/design.md`. Add focused tests with behavior changes; do not report missing tests as passing. Typography uses system font stacks; builds do not fetch Google fonts. A sandboxed Turbopack build may need local socket/process permission for CSS compilation. Update architecture and relevant docs when behavior, contracts, operations, or configuration change; record checks and limitations in the handoff.

## Security and side effects
Never output secrets, environment file contents, credentials, authorization headers, or sensitive provider payloads in logs, docs, commands, or responses. Refer to environment variable names only. Keep privileged clients server-only. Do not expose Supabase secret keys to browsers. Use isolated mocks/local fixtures for tests; external API, ingestion, embedding, generation, and cron calls may incur cost or mutate data and require explicit task authorization.

Never present placeholder strengths, uncalibrated labels, or retrieved snippets as verified measurements or claim-level proof. Preserve stored commentary wording; label it retrospective or synthetic. A kickoff, replay date, or cache update is not a historical information cutoff. Never export provider rows or derived snippets without source-specific rights approval; the 104 wcl-curated-2026-v3 records and original retrospective copy have a scoped owner-directed noncommercial editorial decision; retained original synthetic tests have separate provenance. Neither decision permits provider exports or changes unrelated UNKNOWN rights. Do not upgrade old UNKNOWN sources or claim blanket permission, an open-data licence or trademark clearance. Curated editorial copy is separate from Match Lens pipeline output; date-only facts must not acquire fabricated kickoff timestamps.

WCL_DEPLOYMENT_MODE must fail closed to demo-only when absent/invalid. Exact archive-enabled is for separately configured local/private use. Keep archive and all authoring/cron guards server-side, before auth/work; never add a URL/client override. Public demos must need no service credentials. Public curated records, synthetic test fixtures and private archive data must remain separate; never silently substitute among them. Old illustrative selections redirect to `/?mode=curated`, not to fictional output or the private archive. No synthetic fixtures/helpers belong in the runtime import graph.

Never auto-commit, push, deploy, or mutate production data without explicit instruction. Do not install dependencies, change environment files, or create migrations unless within the authorized task. Report security uncertainties without inventing deployed protections.

Public copy should be concise, factual and editorial. Keep original editorial Match Lenses separate from synthetic tests and actual private cached AI output. Do not label authored retrospectives as model-generated, expose invented predictions or fill missing evidence with generic tactical prose. Preserve separate final-goal and shootout scores; null extra-time status must stay unknown. Put detailed limitations in About/source disclosures while preserving a short non-affiliation footer. Do not duplicate the featured match in secondary listings or publish design mockups as screenshots. Verify real browser behavior before claiming visual/accessibility QA.

Backend verification: `npm run db:test` (or `db:bootstrap`) creates/tests/destroys its own PostgreSQL/pgvector instance and accepts no remote database URL. Requires Docker daemon or installed PostgreSQL/pgvector. `npm run check:credentials` checks reviewable files without printing values. Never report PostgreSQL integration success from mocks. The Supabase CLI adapter is optional and not equivalent to executed gateway/Auth tests. New private authoring requires contract v1 and `WCL_AUTHORING_DATASET_VERSION`; version source/input/prompt/schema changes rather than deleting history. Cutoff eligibility requires publication and capture evidence plus exact input attestation; legacy records remain retrospective and unknowns stay null. Do not serialize persistence checkpoints or upstream error bodies. SQL default-denies provider publication; public archive grants must never be broadened merely to populate a demo.
